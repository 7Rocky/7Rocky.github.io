We are given the following source code in Python, with the output as a multi-line string:

from Crypto.Util.number import *

FLAG = 'maltactf{???????????????????????????????}'
assert len(FLAG) == 41

p = getPrime(128)
q = getPrime(128)
N = p * q
e = 65537

m = f'The flag is {FLAG}'
c = pow(bytes_to_long(m.encode()), e, N)

# ERROR: Sentences should end with a period.
m += '.'
c += pow(bytes_to_long(m.encode()), e, N)

# All good now!
print(f'{N = }')
print(f'{c = }')

'''
N = 83839453754784827797201083929300181050320503279359875805303608931874182224243
c = 32104483815246305654072935180480116143927362174667948848821645940823281560338
'''

Source code analysis

The source code is short and straight-forward:

  • We know the flag format and its length
  • The program generates two 128-bit prime numbers $p$ and $q$ (RSA private key)
  • and uses that to create an RSA public key $N = p \cdot q$ and $e = 65537$
  • After that, the program encrypts a message that contains the flag: $c = m^e \mod{N}$
  • Then, it updates $c$ in a weird way to “add a period”

We are given $N$ as N and the updated $c$ as c. With this information, we need to find the flag.

Solution

Let $m$ be the original message and $m’$ the updated message with the period. Therefore, $m’ = 256 m + 46$, where 46 is the ASCII decimal value of a period.

As a result, the given c value is $c’$:

$$ \begin{align*} c' & = c + \big((m')^e \mod{N}\big) \\ & = (m^e \mod{N}) + \big((m')^e \mod{N}\big) \\ & = \big(m^e + (m')^e\big) \mod{N} \\ & = \big(m^e + (256 m + 46)^e\big) \mod{N} \\ \end{align*} $$

In brief, we can define a polynomial $f(x) = x^e + (256 x + 46)^e - c’$, such that $m$ is a root of $f$ in $\mathbb{Z}/N\mathbb{Z}$. However, finding roots under a composite modulus with unknown factorization is difficult.

In a secure RSA implementation, such as RSA-2048 or RSA-4096, this would be impossible to solve in a reasonable time. However, this time the server uses RSA-256, since the primes $p$ and $q$ are 128-bit numbers. We could use tools like cado-nfs to factor $N$, but this time, the number was already uploaded to factordb:

$ sage -q

sage: c = 32104483815246305654072935180480116143927362174667948848821645940823281560338

So, given that we know $p$ and $q$ such that $N = p \cdot q$, we can find $m$ within the roots of $f$ in $\mathbb{Z}/N\mathbb{Z}$. For this, we can consider $f$ separately in $\mathbb{F}_p$ and $\mathbb{F}_q$, find possible roots and then apply the Chinese Remainder Theorem (CRT).

In other words, we can easily find $m_p$ such that $f(m_p) \equiv 0 \pmod{p}$ and $m_q$ such that $f(m_q) \equiv 0 \pmod{q}$, which means

$$ \begin{cases} m \equiv m_p \pmod{p}\\ m \equiv m_q \pmod{q}\\ \end{cases} $$

Implementation

In SageMath, we could be tempted to use the following code:

sage: Pp.<xp> = PolynomialRing(GF(p))
sage: Pq.<xq> = PolynomialRing(GF(q))
sage: 
sage: fp = xp ** e + (256 * xp + 46) ** e - c
sage: fq = xq ** e + (256 * xq + 46) ** e - c
sage: 
sage: fp.roots()
sage: fq.roots()

However, this will take a long time to finish. A fast way to get a root is to use any_root:

sage: fp.any_root()
38745752538982310497402322032299730998

We can do the same with $f$ defined in $\mathbb{F}_q$ and compute the CRT. Obviously, there can be many roots, so we need to run any_root several times until getting the desired one. Nevertheless, even if we find the desired roots, we won’t be able to get the expected message. Notice that the flag is 41 bytes long, so the message $m$ is 53 bytes long because of "The flag is ". Remember that $n = p \cdot q$ is a 256-bit integer, so 32 bytes long. Therefore, instead of finding the expected message $m$, we will be getting $m \mod{N}$, and it won’t be trivial to find $m$.

The way to address this is issue to consider the known bytes, so that $x = M + 256 y$, where $M$ is the integer value of "The flag is maltactf{\0\0...\0}", and $y$ is the unknown integer value of the inner flag, replacing the null bytes. With this, the new unknown $y$ is only 31 bytes long (41 minus the length of "maltactf{}"), which is less than $N$; and therefore we will find the exact value. So, this is the polynomial after the change of variable:

$$ f(y) = (M + 256 y)^e + \big(256 \cdot (M + 256 y) + 46\big)^e - c' $$

sage: M = int.from_bytes(b'The flag is maltactf{???????????????????????????????}'.replace(b'?', b'\0'))
sage: 
sage: fp = (M + 256 * yp) ** e + (256 * (M + 256 * yp) + 46) ** e - c
sage: fq = (M + 256 * yq) ** e + (256 * (M + 256 * yq) + 46) ** e - c

Now, using any_root several times on both fp and fq and trying the CRT, we will eventually find the flag.

Trick for finding roots

However, there is another way to compute roots of a polynomial under a finite field, which is an implementation trick in SageMath.

Let’s consider $g(t) = t^r - t$ in $\mathbb{F}_r$, where $r$ is a prime number. We know that $g(t) = 0$ for any $t \in \mathbb{F}_r$ because $t^r \equiv t \pmod{r}$ (Fermat’s little theorem), and $t - t = 0$. In other words, all elements of $\mathbb{F}_r$ are a root of $g$, which means that $g$ can be rewritten as:

$$ g(t) = \prod_{a \in \mathbb{F}_r} (t - a) = t (t - 1) (t - 2) \cdots (t - (r - 1)) $$

Let’s return to the challenge. Theoretically, $f$ has at least one root (we know it exists since the flag satisfies the equation). Without loss of generality, let’s consider $f_p$ to be $f$ under $\mathbb{F}_p$ and $g_p(y) = y^p - y$. Remember that $g_p(y) = 0$ for any element of $\mathbb{F}_p$. Hence, the roots of $f_p$ also are roots of $g_p$. As a result, we can use the polynomial greatest common divisor (GCD) to consider only common roots (precisely, the ones we want from $f_p$), so

$$ h_p = \gcd{(f_p, g_p)} $$

However, we can’t simply define $g_p$ in SageMath like yp ** p - yp, because it will complain that the exponent is huge. Instead, remember this GCD property: $\gcd{(f_p, g_p)} = \gcd{(f_p, g_p \mod{f_p})}$. We can use this property in a tricky way to define $g’_p = g_p \mod{f_p} = (x^p - x) \mod{f_p}$ as pow(yp, p, fp) - yp.

So, this way we can get all possible roots of $f$ in $\mathbb{F}_p$ and in $\mathbb{F}_q$:

sage: roots_p = fp.gcd(pow(yp, p, fp) - yp).roots(multiplicities=False)
sage: roots_q = fq.gcd(pow(yq, q, fq) - yq).roots(multiplicities=False)

Flag

At this point, we only need to consider each possible pair, compute the CRT and see if the result is the expected flag:

sage: from itertools import product
sage: from Crypto.Util.number import long_to_bytes
sage: 
sage: for rp, rq in product(roots_p, roots_q):
....:     if (data := long_to_bytes(crt([int(rp), int(rq)], [p, q]))).isascii():
