We are given the following Python source code that encrypts the flag:

import secrets

p = 0x31337313373133731337313373133731337313373133731337313373133732ad
a = 0xdeadbeefdeadbeefdeadbeefdeadbeefdeadbeefdeadbeefdeadbeefdeadbeef
b = 0xdeadc0dedeadc0dedeadc0dedeadc0dedeadc0dedeadc0dedeadc0dedeadc0de

def lcg(x, a, b):
    while True:
        yield (x := a*x + b)

flag = open('flag.txt', 'rb').read()
x = int.from_bytes(flag + secrets.token_bytes(30-len(flag)), 'big')
gen = lcg(x, a, b)

h1 = next(gen) * pow(next(gen), -1, p) % p
h2 = next(gen) * pow(next(gen), -1, p) % p

with open('output.txt', 'w') as o:
    trunc = 48
    # oops, i forgot the last part
    o.write(f'hint1 = {h1 >> trunc}\n')
    o.write(f'hint2 = {h2 >> trunc}\n')

And we also have the output.txt file:

hint1 = 77759147870011250959067600299812670660963056658309113392093130
hint2 = 50608194198883881938583003429122755064581079722494357415324546

Source code analysis

Luckily for us, the code is short. It starts by defining three integer numbers $p$, $a$ and $b$, which are used to define a generator lcg:

p = 0x31337313373133731337313373133731337313373133731337313373133732ad
a = 0xdeadbeefdeadbeefdeadbeefdeadbeefdeadbeefdeadbeefdeadbeefdeadbeef
b = 0xdeadc0dedeadc0dedeadc0dedeadc0dedeadc0dedeadc0dedeadc0dedeadc0de

def lcg(x, a, b):
    while True:
        yield (x := a*x + b)

The above generator implemente a Linear Congruential Generator (LCG), which is normaly used as a pseudo-random number generator (PRNG). For instance, Glibc and Java use LCG-based PRNGs.

The seed of the LCG is the flag as an integer value with some random bytes at the end:

flag = open('flag.txt', 'rb').read()
x = int.from_bytes(flag + secrets.token_bytes(30-len(flag)), 'big')
gen = lcg(x, a, b)

Then, the program computes two values h1 and h2 that depend on the LCG steps (4 steps in total):

h1 = next(gen) * pow(next(gen), -1, p) % p
h2 = next(gen) * pow(next(gen), -1, p) % p

Finally, we are given truncated values of these h1 and h2. Particularly, the program removes the 48 least significant bits:

with open('output.txt', 'w') as o:
    trunc = 48
    # oops, i forgot the last part
    o.write(f'hint1 = {h1 >> trunc}\n')
    o.write(f'hint2 = {h2 >> trunc}\n')

Linear Congruential Generator

Let’s define the LCG in math terms as follows:

$$ \begin{cases} s_0 = x \\ s_i = a \cdot s_{i - 1} + b \;, \qquad i \geqslant 1 \end{cases} $$

Notice that we are missing the “Congruential” part of the LCG because there is no modulus.

The LCG steps are usually defined in a recursive way, but we can transform the expression:

$$ \begin{align*} s_1 & = a \cdot s_0 + b \\ & = a \cdot x + b \\ s_2 & = a \cdot s_1 + b \\ & = a \cdot (a \cdot x + b) + b \\ & = a^2 x + (a + 1) \cdot b \\ s_3 & = a \cdot s_2 + b \\ & = a \cdot (a^2 x + (a + 1) \cdot b) + b \\ & = a^3 x + (a^2 + a + 1) \cdot b \\ s_i & = a \cdot s_{i - 1} + b \\ & = a \cdot (a^{i - 1} x + (a^{i - 2} + \dots + a + 1) \cdot b) + b \\ & = a^i x + (a^{i - 1} + \dots + a^2 + a + 1) \cdot b \end{align*} $$

With this, we have expressed the LCG steps in terms of the initial seed $x$:

$$ s_i = a^i \cdot x + b \cdot \sum_{k = 0}^{i - 1} a^k $$

Notice that LCGs are not secure, because leaking a single $s_i$ will allow to recover previous states and to predict future steps. For this reason, the steps of the LCGs are usually truncated, in order to prevent adversaries from cracking the PRNG (or at least, making it more difficult to crack).

Analyzing the output

Let’s express $h_1$ in math terms:

$$ h_1 = s_1 \cdot {s_2}^{-1} \mod{p} $$

If we expand the values $s_1$ and $s_2$, we get

$$ h_1 = (a x + b) \cdot (a^2 x + (a + 1) \cdot b))^{-1} \mod{p} $$

We can do the same with $h_2$, which depends on $s_3$ and $s_4$:

$$ \begin{align*} h_2 & = s_3 \cdot {s_4}^{-1} \mod{p} \\ & = (a^3 x + (a^2 + a + 1) \cdot b) \cdot (a^4 x + (a^3 + a^2 + a + 1) \cdot b))^{-1} \mod{p} \end{align*} $$

But we are not given $h_1$ nor $h_2$… That would be too easy. Instead, we have:

$$ \begin{cases} \mathrm{hint}_1 = h_1 \gg 48 = \lfloor h_1 / 2^{48} \rfloor \\ \mathrm{hint}_2 = h_2 \gg 48 = \lfloor h_2 / 2^{48} \rfloor \\ \end{cases} $$

Solution

Whenever you see truncated outputs in a cryptography CTF challenge, it is very likely that the solution is related to Coppersmith method or some lattice-reduction technique. Indeed, the challenge name is Copperbox, which suggests the use of Coppersmith method.

For this, we need to define one or more polynomials modulo an integer such that there is a small root modulo a divisor of the modulo. This time, the modulo $p$ is a prime number, so we don’t have to worry about it.

This small root will be found by Coppersmith method. Technique employs lattice reduction to find another polynomial that shares the same root with the provided modular polynomial. However, the new polynomial is defined in the integers, so computing solutions is efficient.

So, let’s see what values we are missing. Basically,

  • Initial seed $x$ (the flag)
  • Truncated value from $h_1$ (48 bits). Let it be $y$
  • Truncated value from $h_2$ (48 bits). Let it be $z$

Hence, we can express:

$$ \begin{cases} h_1 = (\mathrm{hint}_1 \ll 48) + y = 2^{48} \cdot \mathrm{hint}_1 + y \\ h_2 = (\mathrm{hint}_2 \ll 48) + y = 2^{48} \cdot \mathrm{hint}_2 + z \\ \end{cases} $$

At this point, we can substitute the above values in the previous expressions. To improve readability, let $A_m = a^m + \dots + a + 1$, and also $H_1 = 2^{48} \, \mathrm{hint}_1$, $H_2 = 2^{48} \, \mathrm{hint}_2$, so

$$ \begin{cases} h_1 = (a x + A_0 \cdot b) \cdot (a^2 x + A_1 \cdot b)^{-1} \mod{p} \\ h_2 = (a^3 x + A_2 \cdot b) \cdot (a^4 x + A_3 \cdot b)^{-1} \mod{p} \end{cases} $$

$$ \begin{cases} H_1 + y = (a x + A_0 \cdot b) \cdot (a^2 x + A_1 \cdot b)^{-1} \mod{p} \\ H_2 + z = (a^3 x + A_2 \cdot b) \cdot (a^4 x + A_3 \cdot b)^{-1} \mod{p} \end{cases} $$

So far, so good. But let’s get rid of the modular inverse by multyplying in both sides:

$$ \begin{cases} (H_1 + y) \cdot (a^2 x + A_1 \cdot b) \equiv (a x + A_0 \cdot b) \pmod{p} \\ (H_2 + z) \cdot (a^4 x + A_3 \cdot b) \equiv (a^3 x + A_2 \cdot b) \pmod{p} \end{cases} $$

Now, we can group variables:

$$ \begin{cases} (a \, H_1 + a y - 1) \, a \, x + (H_1 + y) \, A_1 \, b \equiv A_0 \, b \pmod{p} \\ (a \, H_2 + a z - 1) \, a^3 \, x + (H_2 + z) \, A_3 \, b \equiv A_2 \, b \pmod{p} \\ \end{cases} $$

We are left with three variables and two equations. If we didn’t have more information about this system, it would not be solvable. However, this time we know that $y, z < 2^{48}$, so they are short values compared to $a$, $b$ or $p$. These $y, z$ are good candidates to look for small roots. Notice that $x$ can be large, since it is a flag (usually around 30 characters, so around $2^{8 \cdot 30} = 2^{240}$).

One trick is to eliminate the $x$ variable in the equations by combining the two of them. Since the expressions are a bit long, let

$$ \begin{cases} H_y = a \, H_1 + a y - 1 \\ H_z = a \, H_2 + a y - 1 \end{cases} $$

So, we start with

$$ \begin{cases} H_y \, a \, x + (H_1 + y) \, A_1 \, b \equiv A_0 \, b \pmod{p} \\ H_z \, a^3 \, x + (H_2 + z) \, A_3 \, b \equiv A_2 \, b \pmod{p} \\ \end{cases} $$

Then, we put the same coefficient on variable $x$:

$$ \begin{cases} H_y H_z \, a^3 \, x + a^2 H_z \, (H_1 + y) \, A_1 \, b \equiv a^2 H_z \, A_0 \, b \pmod{p} \\ H_y H_z \, a^3 \, x + H_y \, (H_2 + z) \, A_3 \, b \equiv H_y \, A_2 \, b \pmod{p} \\ \end{cases} $$

Now we subtract both equations:

$$ a^2 H_z \, (H_1 + y) \, A_1 \, b - H_y \, (H_2 + z) \, A_3 \, b \equiv a^2 H_z \, A_0 \, b - H_y \, A_2 \, b \pmod{p} \\ $$

Notice that we can simplify a bit the expression and remove the $b$:

$$ a^2 H_z \, (H_1 + y) \, A_1 - H_y \, (H_2 + z) \, A_3 \equiv a^2 H_z \, A_0 - H_y \, A_2 \pmod{p} $$

$$ a^2 H_z \, ((H_1+ y) \, A_1 - A_0) - H_y \, ((H_2 + z) \, A_3 - A_2) \equiv 0 \pmod{p} $$

So we have found a single equation on variables $y$ and $z$. Now we can easily define the polynomial:

$$ P(Y, Z) = a^2 H_Z \, ((H_1+ Y) \, A_1 - A_0) - H_Y \, ((H_2 + Z) \, A_3 - A_2) \pmod{p} $$

Notice that $P(y, z) = 0$, so it is a root, and indeed small because they are bounded by $2^{48}$. As a result, we can use a bivariate Coppersmith method to find both values. Once we have them, it is trivial to find $x$:

  • First we find $h_1$:

$$ h_1 = 2^{48} \cdot \mathrm{hint}_1 + y \\ $$

  • Next, we solve for $x$:

$$ \begin{align*} h_1 & \equiv (a x + A_0 \cdot b) \cdot (a^2 x + A_1 \cdot b)^{-1} \pmod{p} \\ (a^2 x + A_1 \cdot b) \cdot h_1 & \equiv (a x + A_0 \cdot b) \pmod{p} \\ a^2 \, h_1 \, x + A_1 \, h_1 \cdot b & \equiv a x + A_0 \cdot b \pmod{p} \\ (a^2 \, h_1 - a) \, x & \equiv A_0 \cdot b - A_1 \, h_1 \cdot b \pmod{p} \\ x & \equiv b \, (A_0 - A_1 \, h_1) \, (a^2 \, h_1 - a)^{-1} \pmod{p} \\ \end{align*} $$

And with this, we find the flag $x$.

Implementation

In SageMath, we can define the variables $Y$ and $Y$ in $\mathbb{Z}/p\mathbb{Z}$, define the auxiliary values and then defile the polynomial $P(Y, Z)$:

#!/usr/bin/env sage

p = 0x31337313373133731337313373133731337313373133731337313373133732ad
a = 0xdeadbeefdeadbeefdeadbeefdeadbeefdeadbeefdeadbeefdeadbeefdeadbeef
b = 0xdeadc0dedeadc0dedeadc0dedeadc0dedeadc0dedeadc0dedeadc0dedeadc0de

trunc = 48

hint1 = 77759147870011250959067600299812670660963056658309113392093130
hint2 = 50608194198883881938583003429122755064581079722494357415324546


Y, Z = PolynomialRing(Zmod(p), 'Y, Z').gens()

A = [sum(a ** m for m in range(i + 1)) for i in range(4)]

H1 = hint1 << trunc
H2 = hint2 << trunc

HY = a * H1 + a * Y - 1
HZ = a * H2 + a * Z - 1

P = a ** 2 * HZ * ((H1 + Y) * A[1] - A[0]) - HY * ((H2 + Z) * A[3] - A[2])

Now, we use Coppersmith method to compute the small roots $y$ and $z$. I will be using defund’s implementation:

load('coppersmith.sage')
y, z = small_roots(P, (2 ** trunc, 2 ** trunc))[0]
print(f'{y = }; {z = }')

Finally, we compute the $x$ value to get the flag:

h1 = H1 + y
h2 = H2 + z

x = b * (A[0] - A[1] * h1) * pow(a ** 2 * h1 - a, -1, p) % p
assert x == b * (A[2] - A[3] * h2) * pow(a ** 4 * h2 - a ** 3, -1, p) % p

print(bytes.fromhex(hex(x)[2:]))

Flag

If we run the script, we will get the flag (a nice easter egg is that the random padding L\xc6 looks like LCG):

$ sage solve.sage
y = 53006259096585; z = 248699398699637
b'HTB{sm1th1ng_mY_c0pp3r_fl4G}L\xc6'

The full script can be found in here: solve.sage.
