Source code analysis

A quick look at julius_encrypt tells us that it is using a Caesar cipher (the name of the challenge is kind of a hint):

def julius_encrypt(msg, shift):
    ct = ''
    for p in msg:
        if p == ' ':
            ct += '0'
        elif not ord('A') <= ord(p) <= ord('Z'):  
            ct += p
        else:
            o = ord(p) - 65
            ct += chr(65 + (o + shift) % 26)
    return ct

This means that the encryption is just a substitution cipher where each plaintext letter is shifted by a fix number to get the ciphertext letter:

However, there is an encrypt function that wraps the use of julius_encrypt:

def encrypt(msg, key):
    for shift in key:
        msg = julius_encrypt(msg, shift)  
    return msg

It implements an iterated Caesar cipher… Is this more secure?

Solution

Well, since Caesar cipher is just a shift, it happens that a shift of 26 leaves the plaintext untouched:

>>> julius_encrypt('ASDF', 26)  
'ASDF'

As a result, no matter how many times we apply julius_encrypt, because the shift can be mapped to a value ranging from 0 to 25.

Therefore, we can simply brute force this shift and find the correct plaintext:
