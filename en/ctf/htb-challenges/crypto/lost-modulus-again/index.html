We are given a short Python code to encrypt the flag:

#!/usr/bin/python3
from Crypto.Util.number import getPrime, long_to_bytes, inverse
from os import urandom

class RSA:
    def __init__(self):
        self.p = getPrime(1024)
        self.q = getPrime(1024)
        self.e = 3
        self.n = self.p * self.q
        self.d = inverse(self.e, (self.p-1)*(self.q-1))
    def encrypt(self, data: bytes) -> bytes:
        pt = int(data.hex(), 16)
        ct = pow(pt, self.e, self.n)
        return long_to_bytes(ct)
    def decrypt(self, data: bytes) -> bytes:
        ct = int(data.hex(), 16)
        pt = pow(ct, self.d, self.n)
        return long_to_bytes(pt)

def main():
    flag = open('flag.txt', 'r').read().strip().encode()
    #padding makes everything secure :lemonthink:
    def pad(data: bytes) -> bytes:
        return data+urandom(16)
    crypto = RSA()
    print ('Flag1 :', crypto.encrypt(pad(flag)).hex())
    print ('Flag2 :', crypto.encrypt(pad(flag)).hex())
    print( 'msg1 :', crypto.encrypt(b"Lost modulus had a serious falw in it , we fixed it in this version, This should be secure").hex())
    print( 'msg2 :', crypto.encrypt(b"If you can't see the modulus you cannot break the rsa , even my primes are 1024 bits , right ?").hex())
if __name__ == '__main__':
    main()

Source code analysis

The above are 4 ciphertexts of an RSA-2048 encryption. We know that the exponent is $e = 3$, but we do not have the modulus $n$:

class RSA:
    def __init__(self):
        self.p = getPrime(1024)
        self.q = getPrime(1024)
        self.e = 3
        self.n = self.p * self.q
        self.d = inverse(self.e, (self.p-1)*(self.q-1))
    def encrypt(self, data: bytes) -> bytes:
        pt = int(data.hex(), 16)
        ct = pow(pt, self.e, self.n)
        return long_to_bytes(ct)
    def decrypt(self, data: bytes) -> bytes:
        ct = int(data.hex(), 16)
        pt = pow(ct, self.d, self.n)
        return long_to_bytes(pt)

For the first 2 ciphertexts (say $c_1$ and $c_2$), the flag is first padded with a random string of 16 bytes and then encrypted with RSA. The last 2 ciphertexts (say $c_3$ and $c_4$) correspond to some known messages hard-coded on the source code (say $m_3$ and $m_4$).

Solution

First of all, we need to get $n$. Notice that using the known messages $m_3$ and $m_4$, we get:

$$ \begin{align} c_3 = m_3 ^ e \mod{n} \iff m_3 ^ e - c_3 \equiv 0 \pmod{n} \\ c_4 = m_4 ^ e \mod{n} \iff m_4 ^ e - c_4 \equiv 0 \pmod{n} \end{align} $$

Therefore, $m_3 ^ e - c_3$ and $m_4 ^ e - c_4$ are both multiple of $n$, so we can find $n$ using the Greatest Common Divisor (GCD):

$$ n = \gcd(m_1 ^ e - c_1, m_2 ^ e - c_2) $$

Now, to find the flag, the key point is that the plaintexts, before encrypting, are very related. Actually, we can denote the ciphertexts like:

$$ \begin{align} c_1 = (256^{16} \;\mathrm{flag} + r_1) ^ e \mod{n} \\ c_2 = (256^{16} \;\mathrm{flag} + r_2) ^ e \mod{n} \end{align} $$

Where $r_1$ and $r_2$ are the random 16-byte strings. Also notice that since padding is byte concatenation, we can express it in numerical terms with a multiplication times $256^{16}$.

Since the padding is short and $e = 3$, we can apply the Coppersmith’s attack (actually, variants called Franklin–Reiter related-message attack and Coppersmith’s short-pad attack). For this, we define two polynomials:

$$ \begin{cases} f(x, y) = x^e - c_1 \mod{n} \\ g(x, y) = (x + y)^e - c_2 \mod{n} \end{cases} $$

Let’s say $R = r_2 - r_1$. These polynomials satisfy that

$$ \begin{align} f(256^{16} \;\mathrm{flag} + r_1, R) & = (256^{16} \;\mathrm{flag} + r_1)^e - c_1 \mod{n} \\ & = 0 \\ \\ g(256^{16} \;\mathrm{flag} + r_1, R) & = (256^{16} \;\mathrm{flag} + r_1 + R)^e - c_2 \\ & = (256^{16} \;\mathrm{flag} + r_2)^e - c_2 \mod{n} \\ & = 0 \end{align} $$

So, the point $(256^{16} \;\mathrm{flag} + r_1, R)$ is a common root of polynomials $f$ and $g$. We are interested in finding $F$, but we will need to find $R$ first. For this, let’s take the resultant of these polynomials in the $x$ variable (kind of eliminating this variable):

$$ h(y) = \mathrm{res}_x(f, g) $$

As a result, $h(R) = 0$, so we know that $R$ is a root of $h$. Notice that the polynomials $f$, $g$, $h$ are defined over $\mathbb{Z}/n\mathbb{Z}$, which is not a field and we can’t easily find $p$ and $q$ such that $n = p \cdot q$. This means that finding this root $R$ is hard.

However, this root $R$ (16 bytes) is small compared to $n$ (2048 bits, 256 bytes). So, we can use Coppersmith method to find $R$.

Once we have $R$, we can update our previous polynomials $f$ and $g$ to:

$$ \begin{cases} F(t) = f(t, R) = t^e - c_1 \mod{n} \\ G(t) = g(t, R) = (t + R)^e - c_2 \mod{n} \end{cases} $$

Therefore, we have that $F(256^{16} \;\mathrm{flag} + r_1) = G(256^{16} \;\mathrm{flag} + r_1) = 0$, so $256^{16} \;\mathrm{flag} + r_1$ is a root of both $F$ and $G$. As a result, we can apply Franklin-Reiter related-messages attack, which consists basically in computing the polynomial GCD of these polynomials, to find the shared factor $(t - (256^{16} \;\mathrm{flag} + r_1))$, and obtain the flag.
